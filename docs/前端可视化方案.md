# RepoPilot-MAS 前端可视化与控制面板方案（v3：Streamlit + 三阶段）

> 状态：**阶段一/二/三全部完成并通过验收**
> 技术选型：**Streamlit 面板 + FastAPI 服务**（纯 Python 栈，复用现有 Runtime）
> 原则：前端与服务只做执行引擎的"另一个消费者"；不修改 Engine/Supervisor/Worker 行为；服务运行产物与正式评测/冻结身份完全隔离。
> 注：三个子阶段统称为计划基线"Phase 7：可视化与控制面"，不与现有 Phase 0-6 编号冲突。

---

## 1. 背景与目标

RepoPilot-MAS 的核心价值是"Supervisor 动态决策 + Engine 确定性约束 + 四类 Worker 协作 + 真实验证闭环"，目前只存在于 JSONL Trace 与 Checkpoint 中。

本阶段目标：

1. 把动态 TaskGraph 生长、Fork–Join、Challenge/Rebuttal、双补丁竞争、失败归因可视化；
2. 暴露 LangGraph 已内置但未使用的**人工审批通道**（`require_human_approval` / `interrupt` / `resume`）；
3. 提供**常驻运行模式**：界面提交任务 → 实时运行 → 中途审批 → 事后复盘，形成完整可用闭环；
4. 借鉴 LangGraph Studio（节点检查）、OpenHands（diff/事件流）、Langfuse（调用明细）的交互模式。

## 2. 三阶段总览

| 阶段 | 主题 | 核心能力 | 工作量 |
| --- | --- | --- | --- |
| 阶段一 | 只读驾驶舱 | 浏览全部真实运行、动态任务图回放、失败归因 | 约 1 周 |
| 阶段二 | 常驻运行模式 | 界面提交受信任务、实时运行、web_runs 隔离 | 约 4-5 天 |
| 阶段三 | 人工审批控制面 | 关键决策批准/拒绝、暂停/恢复/取消/终止 | 约 2-3 天 |

每个阶段独立可验收、独立可演示；阶段一不依赖二/三，阶段二、三依赖阶段一的数据服务。

## 3. 阶段一：只读驾驶舱（可视化核心）

### 3.1 内容

**后端（FastAPI 只读服务）**

**前端（Streamlit 页面）**

1. 仪表盘 `/`：运行列表（run-id、split、frozen、passed、solved/N、耗时、Token、API 调用）、聚合指标卡、失败类别分布柱状图、路由分布；

3. 对比页：多 run 对比、同一任务跨运行对比（展示"模型方差"）。

**演示数据**

- 真实运行：`reports/closed_loop/evaluation/`（dev5 系列、frozen10_explore_v1 等）；

4. Phase5 机制 Trace 可完整展示；

## 4. 阶段二：常驻运行模式（界面提交任务）

### 4.1 内容

**常驻服务**

- FastAPI 常驻进程启动时加载 2×Qwen3-8B 模型池（复用现有 `WorkerPool.prepare()`），服务运行期间模型只加载一次；
- `POST /runs`：选择受信 TaskSpec（`data/quixbugs/tasks/*.json`）+ 运行参数（run 标签、是否需审批）→ 服务内启动单任务运行；
- 运行产物写入独立目录 `reports/web_runs/<run_id>/`，与正式评测目录、冻结身份完全隔离；
- 任务级串行运行；进度通过轮询接口（2-3s）暴露。

**前端**

- 任务表单页：TaskSpec 下拉选择、参数配置、提交按钮；
- 实时进度视图：任务状态、当前阶段、最近事件（轮询刷新）。

### 4.2 验收标准

1. 界面可提交受信 QuixBugs 任务并看到实时运行直至结束；
2. 运行结果落盘 `reports/web_runs/`，不污染 `reports/closed_loop/evaluation/`；
3. 服务重启后模型池可正常释放/重载，不泄漏显存；
4. web_runs 产物可被阶段一的仪表盘与详情页直接浏览。

## 5. 阶段三：人工审批控制面

### 5.1 内容

**审批通道对接**

- 现状：LangGraph Runtime 已内置 `require_human_approval` 与 `interrupt`；`_route_after_supervisor` 在派发前进入 `human_review` 节点等待；恢复走 `resume(thread_id, task_id, expected_state_version, human_response)`。
- 服务新增控制接口：查询待审批决策、提交 `approved/denied`、暂停/恢复/取消/终止；内部调用现有 Runtime `resume()` / Engine 决策 API，**不新写执行逻辑**。

**前端**

- 审批队列页：待审批决策（action、reason、证据引用、ready_worker_ids），一键批准/拒绝；
- 拒绝语义与现有 `human_rejected` 一致：拒绝后不派发，返回 Supervisor 重新决策；
- 任务操作按钮：暂停/恢复/取消/终止；
- 审批队列 2-3s 轮询（P2 再升级 WebSocket）。

### 5.2 验收标准

1. 审批模式下任务在关键决策点挂起并出现在审批队列；
2. 批准后任务继续运行；拒绝后不派发并返回 Supervisor 重新决策，行为与现有 `resume()` 一致；
3. 暂停/恢复/取消/终止可用，Checkpointer 状态一致；
4. 控制接口仅本机可访问（bind 127.0.0.1）。

### 5.3 阶段三验收结果（已完成）

- [x] `WebTaskRunner` 支持 `require_human_approval=True`：**审批模式使用同步 LangGraphRuntime**（async 图中 `interrupt()` 依赖的 runnable context 在 langgraph 1.x 异步执行路径不可用，已在 `langgraph_runtime.py` 为 `AsyncLangGraphRuntime` 提供 `_ahuman_review_node` 异步节点并保持同步类行为不变）；
- [x] 审批循环：任务在 `human_review` interrupt 挂起 → 控制接口批准/拒绝 → 重建 runtime（同一 sqlite Checkpoint）→ `resume` 继续 / `human_rejected` 结构化收尾；
- [x] 接口：`GET /approvals`、`GET /runs/{id}/pending`、`POST /runs/{id}/approve`（`approved: true/false`）；
- [x] 前端"审批队列"页：轮询挂起审批、展示决策 action/理由/待派发 Worker、一键批准/拒绝；
- [x] 测试：审批挂起/批准恢复/拒绝不派发/无挂起 409 等专项测试通过；全量 pytest 与 Ruff 通过；
- [x] 真实冒烟：审批任务提交 → 状态机正常收敛；因当前 API 额度耗尽，真实审批挂起点未触发（额度恢复后可在界面上完整验证批准/拒绝流程）。

## 6. 技术架构

```
┌───────────────┐     HTTP/REST      ┌───────────────────────────────┐
│ Streamlit 面板 │ ─────────────────▶ │  FastAPI 服务（常驻）           │
│ （纯 Python）   │ ◀───────────────── │  ├ 只读：reports/** 产物        │
└───────────────┘      JSON          │  ├ 控制：审批/暂停/恢复/取消      │
                                     │  └ 运行：常驻 Worker 模型池      │
                                     └──────────┬────────────────────┘
                                                │
          ┌─────────────────────────────────────┼───────────────┐
          ▼                                     ▼               ▼
  reports/**/trace.jsonl              langgraph.sqlite3    常驻 WorkerPool
  reports/**/result.json               （恢复/审批状态）      （Qwen3-8B ×2）
  reports/web_runs/**/run.json
```

- 前端（Streamlit）：页面 = 仪表盘 / 任务详情 / 任务表单 / 审批队列 / 对比；图表 = plotly（任务图、柱状图）+ pandas 表格；diff 高亮用 `diff-match-patch` 或 `rich` 渲染；
- 后端（FastAPI）：只读接口（核心）+ 控制接口 + 运行接口（阶段二/三开启）；
- 安全：默认只读；控制/运行接口显式开启；bind 127.0.0.1；不做用户系统（P2）。

## 7. 范围与边界

- **不做**：WebSocket（P2）、多用户/权限/任务队列（P2/P3）、任意仓库任务（保持受信 QuixBugs 边界）、修改评测协议/预算/任务集（永远不做）；
- **不动**：Engine/Supervisor/Worker 行为、Phase 0-6 验收门、正式评测与冻结流程。
